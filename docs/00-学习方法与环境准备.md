# 00 学习方法与环境准备

## 本章目标

这一章不讲复杂技术，只解决三个问题：

1. Spec Engineer 到底需要学到什么深度？
2. 如何建立自己的学习环境？
3. 学习过程中应该持续产出什么？

## 一、Spec Engineer 不是程序员，但必须具备“工程可读性”

Spec Engineer 的目标不是写最多代码，而是能准确描述系统应该怎样工作，并让产品、开发、测试对同一需求形成一致理解。

因此你不需要一开始就系统学习某种编程语言，但必须逐渐读懂以下内容：

- URL、HTTP 方法、请求与响应
- JSON、YAML
- SQL 基础
- 表、字段、主键、外键、索引
- API endpoint
- HTTP 状态码
- 日志
- 认证 Authentication 与授权 Authorization
- Git commit / branch / pull request
- 基本架构图
- 前端、后端、数据库、缓存、消息队列等常见组件

你的技术学习目标是：**能够和开发人员进行精确沟通，并能把技术约束写进 Spec。**

## 二、建议准备的软件

### 必须

- GitHub 账号
- VS Code
- Git
- 浏览器
- draw.io 或任意流程图工具

### 推荐

- Postman：理解和测试 API
- DBeaver 或 SQL Server Management Studio：查看数据库
- Swagger Editor：查看 OpenAPI
- Markdown 编辑器
- Mermaid：用文本维护流程图和时序图

GitHub 本身支持在 Markdown 中直接渲染 Mermaid，因此本仓库后续很多图可以直接以文本方式维护。

## 三、先掌握 Markdown

Spec 文档经常需要版本管理，Markdown 非常适合工程团队。

你至少需要会：

- 标题
- 有序/无序列表
- 表格
- 引用
- 链接
- 代码块
- Mermaid 图

示例：

    # 登录模块

    ## 功能需求

    | ID | Requirement |
    |---|---|
    | AUTH-001 | 用户可通过用户名和密码登录 |

## 四、建立自己的“案例项目”

不要每章都换案例。推荐从第一章开始选择一个简单 SaaS，一直使用到最终实战。

本仓库默认案例：

**医疗预约 SaaS**

最初只有四个角色：

- 患者
- 医生
- 前台
- 系统管理员

最初只有五个功能：

- 登录
- 患者建档
- 医生排班
- 预约
- 取消预约

后续每学一个知识点，就在这个项目中补一层 Spec。

## 五、学习笔记结构

每章新建一份自己的笔记，固定包含：

### 1. 我学到的概念

用自己的话解释。

### 2. 我仍然不理解的问题

不要删除，后面回来补。

### 3. 对案例项目有什么影响

例如学习 HTTP 后，记录：

- 创建预约应该用 POST
- 查询预约列表应该用 GET
- 取消预约可以考虑状态变更，而不是直接删除数据库记录

### 4. 本章产出物

只有“产出物完成”才算本章完成。

## 六、不要陷入工具学习

工具只是载体。

不要因为“我不会 Jira”就认为不会需求工程。真正重要的是：

- 是否知道需求生命周期
- 是否知道谁提出需求
- 是否知道如何澄清
- 是否知道如何记录决策
- 是否知道如何追踪变更
- 是否知道如何验证

Jira、Confluence、DOORS、Polarion、Codebeamer 都是在实现这些方法。

## 七、本章练习

1. 在本仓库中新建个人学习分支。
2. 用 Markdown 写一页“我的案例项目”。
3. 写出该项目的 5 个核心功能。
4. 写出 4 个用户角色。
5. 给每个核心功能编一个 ID，例如 APPT-001。
6. 用 GitHub 提交一次 commit。
