# Spec Engineer 毕业项目任务书

> 目标：不依赖教程答案，从一句模糊业务描述开始，独立完成一套可以交给 Product、Developer、QA 和 AI Coding Agent 使用的 Spec。

# 项目题目

**企业员工请假 SaaS**

原始需求只有一句：

> 公司希望做一个在线请假系统，让员工提交请假、主管审批、HR 管理假期规则。

你必须自行完成需求工程。

---

## Stage 1：业务

提交：

- Business Problem
- 3+ Business Goals
- Success Metrics
- In Scope
- Out of Scope
- 8+ Stakeholders
- Stakeholder Map

最低标准：
- 不得把页面功能直接当 Business Goal。

---

## Stage 2：Elicitation

提交：

- 30 个 Interview Questions
- 10 个 Facts
- 10 个 Assumptions
- 15 个 Open Questions
- As-Is Flow
- To-Be Flow

最低标准：
- Fact / Assumption / Question 必须分开。

---

## Stage 3：Glossary 与 Business Rules

至少：

- 20 个术语
- 15 条 Business Rules

例：
- Leave Request
- Leave Balance
- Approval
- Pending
- Approved
- Rejected

---

## Stage 4：Requirements

至少：

- 5 Business Requirements
- 10 User Requirements
- 40 System Requirements
- 15 NFR

每条包含：
- ID
- Type
- Source
- Priority
- Status
- Verification

---

## Stage 5：Modeling

必须有：

- 2 Flowcharts
- 3 Use Cases
- 2 Sequence Diagrams
- 1 Leave Request State Machine
- 1 ER Diagram
- 1 System Context Diagram

---

## Stage 6：Permission

至少角色：

- Employee
- Manager
- HR
- Admin

完成：
- Role Matrix
- Object-Level Rules
- State-Based Rules

---

## Stage 7：API

至少设计：

- login / identity integration
- GET leave-types
- GET leave-balance
- POST leave-requests
- GET leave-requests
- GET leave-requests/{id}
- POST approve
- POST reject
- POST withdraw

每个 API：
- Request
- Schema
- Validation
- Permission
- Success
- 4+ Errors
- Idempotency
- Audit

---

## Stage 8：Data

至少实体：

- Employee
- LeaveType
- LeaveBalance
- LeaveRequest
- Approval
- AuditLog

完成：
- Data Dictionary
- Relationship
- Null
- Enum
- Unique
- Lifecycle
- Sensitive classification

---

## Stage 9：NFR

至少：

- 4 Performance
- 3 Security
- 3 Reliability
- 2 Availability
- 3 Audit
- 3 Observability
- 2 Backup/DR

全部必须可验证。

---

## Stage 10：Acceptance Criteria

至少 25 条。

必须覆盖：
- happy
- invalid input
- permission
- boundary
- state
- duplicate
- concurrency

---

## Stage 11：Testing

至少 50 个 Test Case。

必须使用：
- Equivalence Partitioning
- Boundary Value Analysis
- Decision Table
- State Transition
- Authorization
- Concurrency

---

## Stage 12：Traceability

创建：

```
Business Goal
→ Business Rule
→ Requirement
→ API/Data/Model
→ Test
→ Result
```

不得存在：
- 无测试的 Must Requirement
- 无来源的核心功能

---

## Stage 13：Change Request

变更：

> 公司要求增加“半天假”，并允许主管将已批准请假撤回审批状态。

完成：
- CR
- Impact Analysis
- Requirement Update
- State Update
- API Impact
- Data Impact
- Test Impact
- Compatibility Risk

---

## Stage 14：AI Coding Task

为一个功能创建 AI Coding Spec：

- Goal
- Read First
- Requirements
- Constraints
- Files
- Required Tests
- Stop Conditions
- Done Criteria

要求：

> AI 不得自行补业务规则；发现冲突必须停止并报告。

# 毕业判定

如果把上述目录交给一个没有参加过需求会议的 Developer / QA，他们能够：

- 理解为什么做
- 理解做什么
- 理解不能做什么
- 理解每个对象和状态
- 理解 API/Data
- 理解权限
- 理解异常
- 知道怎样测试

则项目基本达到合格的 Spec 工程作品集标准。
